# Riggverk 2026.11.13

## New

- Turn individual skills off. In Library → Skills, Disable a bundled or pack skill (or type `:disable <name>`). The confirm names the skills that point to it. The next Update removes Riggverk's copies from every agent with a backup and leaves out the rules lines that name the skill. `z` restores the copies but the skill stays off until you Enable it again
- `orchestrate` is a bundled skill. It leads several agents toward one goal with a charter, a ledger, lanes and verified reports, and only when you ask for it. If a skill pack ships its own `orchestrate`, the bundled copy replaces it in one Update
- Code comments: in Library → Rules, choose Harness default (nothing changes), Minimal (comment only what the code cannot show) or Off (only comments the language or tooling requires). The choice reaches every agent's rules at the next Update, and a repository's own comment rules still win
- Claude Code: when the advisor tool is available, the rules and the `implementation-plan`, `minimal-implementation`, `delegate` and `orchestrate` skills ask the agent to consult it before settling on a plan and before calling work done. Riggverk sets no model for it
- The Claude Code page suggests two `permissions.deny` lines that stop Claude's file tools from reading `.env` files, with a Copy button. Riggverk does not write them into your settings
- Linux packages: an AppImage, a deb and an rpm for x86_64, built in an Ubuntu 22.04 container

## Fixes

- Codex: the bundled agents no longer set `sandbox_mode`, which Codex ignores in an agent file. The reviewer agents are read-only by their instructions, under your own sandbox. They set a reasoning effort (low for repo_scout, high for inspector and security_reviewer, medium for verifier) and no model
- Codex: when your config uses a permission profile (`default_permissions` or a `[permissions.*]` table), Riggverk leaves `sandbox_mode` out and the review says why
- Codex: `retro` and `grill-me` start only when you invoke them
- Claude Code: the inspector and sentinel agents run at high effort
- Agents: inspector and sentinel (`security_reviewer` in Codex) say so when the prompt has no diff and review only what they can read, cite `file:line` with a short quote, list what they did not check, and use the prompt's own output format when it gives one. They, repo-scout and verifier treat file content as data, not instructions. verifier reports each check as pass, fail or not run with the command, exit status and an output excerpt, instead of saying whether it is safe to commit. The Cursor repo-scout, inspector, verifier, security-reviewer and browser-qa agents say when to use them and what to pass, the Codex rules name the Codex agents and when to use each, and the Claude Code scribe no longer preloads `current-docs`
- The `.env` check on the Claude Code page reads the deny rules in order, so a later `Read(!…)` exception that reopens `.env` no longer counts as protection
- A disabled skill also leaves the agent-specific lines of the rules that name it
- Several skill descriptions say what the skill is not for, so agents pick the right skill more often
- The `delegate` notes for OpenCode match what Riggverk's architect agent may start
- OpenCode: the repo-scout, inspector, sentinel and scribe agents and the built-in explore agent have no shell, so they cannot change files through it. Give them the diff or the changed files in the prompt
- Riggverk's window stays on its own pages: a link or a script cannot load another site in it
- Use Riggverk's version on a pack skill names what the pack's `SKILL.md` lets the agent do without asking (hooks, allowed-tools and the like), as the Install review does, even when the diff is not shown
- Skill import reads the chosen folder through the folders it opened, so a folder that is replaced by a link during the import is refused instead of followed
- Codex: Keep mine records exactly the values the confirmation showed. If `config.toml` changed in the meantime, nothing is recorded and the page asks you to look again
- The data folder, the backup folder and the folders above them must belong to you or the system and must not be writable by other users; otherwise Riggverk names the folder and why and does not use it. Personal docs are saved only into docs folders that belong to you
- On Linux, a folder only your own user group can write counts as yours, so a pack cloned with the usual settings is no longer refused
- Riggverk runs OpenCode and Python only from folders other users cannot change. An OpenCode it skips for that reason shows as found but not used
- A long workspace folder path stays inside its card on the Overview page. Before, it could make the page wider than a narrow window
- The review map shows when an update writes or removes a skill pack's skills, and the table names how many skills come from each pack. Before, a pack's line looked like a kept, skipped one, so a pack the update installed looked as if it was never installed

## Install

Open `Riggverk-v2026.11.13-macOS.dmg`, drag Riggverk to Applications and open it from there (or unzip `Riggverk-v2026.11.13-macOS.zip` and move `Riggverk.app` to `/Applications`). One app runs on Apple silicon and Intel Macs. Riggverk is ad hoc signed and not notarized, so macOS stops the first launch: open System Settings, Privacy & Security, and choose Open Anyway next to the message about Riggverk. `SHA256SUMS` lists the checksums of every download (`shasum -a 256 -c SHA256SUMS --ignore-missing`).

On Linux (x86_64, glibc 2.35 or newer, such as Ubuntu 22.04 and Fedora 36 or later): make `Riggverk-v2026.11.13-linux-x86_64.AppImage` executable (`chmod +x`) and run it; it updates itself. Or install `Riggverk-v2026.11.13-linux-amd64.deb` (`sudo apt install ./Riggverk-v2026.11.13-linux-amd64.deb`) or `Riggverk-v2026.11.13-linux-x86_64.rpm` (`sudo dnf install ./Riggverk-v2026.11.13-linux-x86_64.rpm`); a package install is updated by installing the next package. Check a download with `sha256sum -c SHA256SUMS --ignore-missing`.
